# Project progress — NFL props / DraftKings modeling pipeline

Updated: 2025-11-17

This document records the current pipeline, recent findings from the logs, known issues, and next actions for the NFL props / betting recommendation app. Use this as the single-page status and reproduction guide for collaborators.

## High-level overview

We build a recommendation tool that:
- Pulls bookmaker odds (DraftKings is the primary target) via TheOddsAPI (v4).
- Normalizes and caches per-event snapshots (all available bookmakers are fetched but DraftKings is preferred for modeling/pricing).
- Enriches odds with player & game-level statistics from Python NFL libraries (nfl_data_py / nflfastR inputs).
- Scrapes ESPN and other web sources for injuries and news to flag edge cases.
- Runs a suite of models (PFR heuristics, nfl_data_py structured features, and other ML/STAT models) to compute model probabilities, edges, and recommended actions.

## Data sources

- Odds: TheOddsAPI v4 — per-event odds, all bookmakers. We request DraftKings explicitly when possible and prioritize DraftKings markets in downstream outputs.
- Play-by-play & historical stats: nfl_data_py (Python) / nflfastR datasets.
- Player pages & gamelogs: Pro-Football-Reference (PFR) HTML scraping as fallback / quick features.
- News & injuries: ESPN team pages, Rotowire, authorative beat reporters and general web scraping for confirmations.

## Recent findings and issues (from logs)

1. OpenAI API outbound failures
   - Repeated: "Request failed: error sending request for url (https://api.openai.com/v1/chat/completions)." (multiple occurrences).
   - Action: add exponential backoff + retries; add alerting for repeated failures; include request metadata in logs for debugging.

2. SSL certificate verification problems
   - Observed while downloading pbp data via nfl_data_py; caused fallback to cached values.
   - Fix used in logs: install certifi and set SSL_CERT_FILE to certifi.where() prior to running Python scripts.
     Example:

     ```bash
     pip install --user certifi
     export SSL_CERT_FILE=$(python3 -c "import certifi; print(certifi.where())")
     python3 scripts/run_v5_models.py
     ```

   - Note: avoid globally disabling SSL verification in production; prefer fixing CA bundles.

3. DraftKings player-prop markets sometimes absent in snapshots
   - Some TheOddsAPI per-event responses do not include DK player prop markets (player_anytime_td, player_1st_td, etc.) at certain timestamps.
   - Mitigations:
     - Persist full per-bookmaker snapshots with timestamps.
     - Implement light polling (safe backoff) to capture late-published markets.
     - Attempt historical or alternate timestamp endpoints if supported by API.

## Recommended operational practices

- Fetch call recommended params (DraftKings-only example):

  ```bash
  curl -sG "https://api.the-odds-api.com/v4/sports/americanfootball_nfl/events/{EVENT_ID}/odds" \
    --data-urlencode "apiKey=${ODDS_API_KEY}" \
    --data-urlencode "bookmakers=draftkings" \
    --data-urlencode "regions=us" \
    --data-urlencode "markets=player_anytime_td,player_1st_td,player_pass_yds,player_receptions,player_rush_yds" \
    -o /path/to/cache/event_${EVENT_ID}.json
  ```

- Retry strategy: exponential backoff with jitter; circuit breaker after N failures to avoid tight retry loops.
- Logging: include timestamps, event_id, bookmaker, markets requested, HTTP status/error text, and local cache path.
